# 등록 키(sk_u·pk_u) 제거 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** IdP 가 사용자 키(pk_u)를 갖지 않게 한다 — 등록·발급·슬롯 조회·세션 폐기를 서명(`sig_u`·`sig_reg`) 대신 π_IdP(공개 입력 `ctx`·`tag`)로 인증한다.

**Architecture:** `pi_idp` 회로에 공개 입력 둘(`ctx`, `tag = Poseidon(T_TAG, s_u, ctx)`)을 붙인다. `ctx` 는 요청 용도·내용의 해시로 회로 밖에서 계산하고, IdP 는 요청 필드에서 스스로 다시 계산해 공개 입력을 조립한다. 발급이 아닌 요청은 세션 부분을 버릴 값으로 채운 같은 증명을 낸다. "등록됨" 의 표지는 `auid` 다.

**Tech Stack:** circom 2 / snarkjs Groth16(`pi_idp` 만 재빌드), Node/Express(`cia.js`, `mode3_wallet_agent.js`), MetaMask Snap(`snap-mode3`, mm-snap build), 정적 HTML(`mode3/*.html`), esbuild 번들(`mode3/user`), Playwright 브라우저 테스트.

**Spec:** `docs/superpowers/specs/2026-11-12-mode3-no-pk-u-design.md`

## Global Constraints

- `pi_idp` 공개 입력 10개, 순서 고정: `[0] uid [1] auid [2] auid_s [3] C_u_x [4] C_u_y [5] C_s_x [6] C_s_y [7] max_height [8] ctx [9] tag`.
- 도메인 상수(ASCII 큰 끝 정수):
  `MODE3TAG` = `5570746328085184839`, `MODE3CTXISSUE` = `6125100363118896915451267470661`, `MODE3CTXREG` = `93461614427473402641139015`,
  `MODE3CTXSLOT` = `23926173293433191076148825940`, `MODE3CTXREVOKE` = `1568025692958437610365359997537093`.
- ctx: 발급 `Poseidon(D_CTX_ISSUE, arid_s, chainid, allowAgent)`, 등록 `Poseidon(D_CTX_REG, n)`, 슬롯 `Poseidon(D_CTX_SLOT, nonce)`, 세션 폐기 `Poseidon(D_CTX_REVOKE, Cf_s, bound, nonce)`.
- 증명 검증 실패 응답은 400 `{ error: 'bad idp proof', reason: 'bad_idp_proof' }`. `bad user signature`·`bad_registration_signature` 는 없어진다.
- **`pi_cred` 는 다시 빌드하지 않는다**(zkey 가 바뀌면 배포된 온체인 검증자와 어긋난다). 회로 빌드는 `bash scripts/build_mode3_circuit.sh pi_idp` 한 번뿐이고 **실행 전에 사용자 승인**을 받는다(Task 1 Step 7).
- 옛 요청 형식과 호환을 두지 않는다. s_u 유도 salt(`zkd/mode3/s_u/v2/<k>`)·auid 식·PPID 식은 바꾸지 않는다.
- IdP 상태 버전 12 → 13. 로더는 12·13 을 받는다. 상태 파일은 지우지 않는다.
- 스냅 버전 `0.3.1 → 0.4.0`(manifest·package.json). 새 의존성 금지.
- 모든 화면 문구·주석·커밋 메시지는 한글(기존 문체). 화면 이름은 "zk 스냅 화면(localhost:5100)", "속성 도구", "IdP 관리자 페이지".
- 커밋은 경로 지정 `git add -- <paths>`(`sui-repo/` 주의), 트레일러 두 줄(`Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>` / `Claude-Session: https://claude.ai/code/session_013qGSXZTftBJSB1M4XpPRHN`).
- 비밀 파일(`.env`, `*_state.json`, `*_keys.json`, `role.env` 등)은 읽지도 출력하지도 않는다. s_u·tag·증명 값은 로그에 찍지 않는다.
- 사용자 프로세스(:5100 에이전트, :8082 스냅 서버)는 건드리지 않는다. hardhat 노드는 :8545 가 비어 있을 때만 직접 띄우고 끝나면 PID 로 끈다.
- 명령의 `$SCRATCH` 는 이 세션의 스크래치패드 디렉터리다(긴 출력은 거기 파일로 보내고 끝만 읽는다). 저장소 안에 임시 파일을 만들지 않는다.
- **이 계획은 배포를 하지 않는다.** VM rsync·IdP 재시작·스냅 재설치·데모 리셋(스펙 §6)은 구현이 끝난 뒤 따로 승인받는다.

async function ctxHash(name, domain, fields) {
  const poseidon = await getPoseidon();
  for (const [k, v] of Object.entries(fields)) {
    if (typeof v !== 'bigint' || v < 0n || v >= poseidon.F.p) throw new Error(`${name}: ${k} 는 [0, p) 범위의 bigint 여야 한다(BN254 스칼라 필드)`);

  return poseidon.F.toObject(poseidon([domain, ...Object.values(fields)]));
}
/** 발급 요청의 ctx = Poseidon(D_CTX_ISSUE, arid_s, chainid, allowAgent). 옛 sig_u 메시지의 나머지(auid_s·C_u·C_s·max_height)는 π_IdP 공개 입력이 이미 덮는다. */
export async function issueCtx({ arid_s, chainid, allowAgent }) {
  if (allowAgent !== 0n && allowAgent !== 1n) throw new Error('issueCtx: allowAgent 는 0n 또는 1n');
  return ctxHash('issueCtx', DOMAIN_MODE3_CTX_ISSUE, { arid_s, chainid, allowAgent });
}
/** 등록 요청의 ctx = Poseidon(D_CTX_REG, n) — n 은 지갑이 뽑은 난수. uid·auid 는 π_IdP 공개 입력이 덮는다. */
export function registerCtx({ n }) { return ctxHash('registerCtx', DOMAIN_MODE3_CTX_REG, { n }); }
/** 슬롯 조회의 ctx = Poseidon(D_CTX_SLOT, nonce). */
export function slotCtx({ nonce }) { return ctxHash('slotCtx', DOMAIN_MODE3_CTX_SLOT, { nonce }); }
/** 세션 폐기의 ctx = Poseidon(D_CTX_REVOKE, Cf_s, bound, nonce) — bound(허용 거래 수)가 인증에 든다. */
export async function revokeSessionCtx({ Cf_s, bound, nonce }) {
  if (typeof bound !== 'bigint' || bound < 0n || bound >= (1n << 32n)) throw new Error('revokeSessionCtx: bound 는 [0, 2^32) bigint');
  return ctxHash('revokeSessionCtx', DOMAIN_MODE3_CTX_REVOKE, { Cf_s, bound, nonce });
}
/** tag = Poseidon(T_TAG, s_u, ctx) — s_u 없이 못 만든다. 증명을 만들기 전에 계산할 수 있어 Google nonce 에 넣는다(lib/mode3_oidc_nonce.js). */
export async function tagOf({ s_u, ctx }) {
  checkScalars({ s_u });
  const poseidon = await getPoseidon();
  if (typeof ctx !== 'bigint' || ctx < 0n || ctx >= poseidon.F.p) throw new Error('tagOf: ctx 는 [0, p) 범위의 bigint 여야 한다(BN254 스칼라 필드)');
  return poseidon.F.toObject(poseidon([DOMAIN_MODE3_TAG, s_u, ctx]));
}

/** V11 §3.1 — s_u 는 2^250 미만, auid = Poseidon(T_AUID, uid, s_u) 를 IdP 에 낸다. 등록 키(sk_u·pk_u)는 2026-11-13 에 없앴다(스펙 2026-11-12 no-pk-u) —

/** 복구 시드(2026-10-21): 32바이트 시드에서 s_u(2^250 미만, randomScalar 와 같은 범위)를 SHA-256 으로 결정적으로 유도한다.
 *  시드(복구 코드)만 보관하면 브라우저 저장소가 지워져도 같은 s_u 로 돌아와 모든 RP 에서 PPID 가 그대로다. 브라우저 번들에서는 createHash 쉼(lib/browser)이 돈다. */
export function registrationSecretsFromSeed(seed) {
  if (!(seed instanceof Uint8Array) || seed.length !== 32) throw new Error('registrationSecretsFromSeed: seed 는 32바이트');
  let v = 0n; for (const b of createHash('sha256').update(new Uint8Array(seed)).update('zkd3/s_u').digest()) v = (v << 8n) | BigInt(b);
  return { s_u: v & (SCALAR_MAX - 1n) };
}
export async function createRegistration(uid, seed = randomBytes(32)) {
  if (typeof uid !== 'bigint') throw new Error('createRegistration(uid: bigint) — auid = Poseidon(T_AUID, uid, s_u) 를 계산하려면 uid 가 필요하다');
  const { s_u } = registrationSecretsFromSeed(new Uint8Array(seed));
  return { s_u, auid: await auidOf({ uid, s_u }), seed: Buffer.from(seed).toString('hex') };
}
