# Mode 3 — zkWrapper 속성 넣기를 /user 로 (설계 초안)

- 작성: 2026-11-25. 상태: **승인(2026-11-25, Q1~Q3 권장대로)·구현, 라이브 5100 재시작 전**. 사용자 결정(B안).
- 목적: salt 가 화면·클립보드를 거치지 않게 한다. 지금은 `/user` "salt 보기" → 복사 → `/attr.html` 에 붙여 넣기다.
- 범위: zkWrapper 만(`WRAP`). passkey-web·snap 등의 도구·"salt 보기"·"속성 저장" 은 그대로다. 회로·서버 API·기록 형식은 바꾸지 않는다.

## 1. 확인한 것
- "내 신원" 카드는 같은 날 화면에서 뺐다(`e142ff4`) → 그 카드를 되살리지 않고 **"내 속성" 카드를 새로** 둔다.
- 기존 "속성 저장"(`core.saveProfile`)은 누르는 즉시 **이 브라우저의 세션을 모두 지우고** 속성을 바꾼다. 등록도 있어야 한다. 새 저장은 이것을 부르지 않고 **기록만** 쓴다(로그인 때 `syncProfileFromRecord` 가 반영하는 지금 길 그대로).
- 로그인이 기록에서 쓰는 것은 `profile` 과 `auid`(패스키 대조)뿐이다. `attrs`·`commit` 은 형식을 맞추려고 남긴다.
- 화면의 속성 칸은 2초마다 **등록된** 값으로 다시 그려진다. 저장한 값은 다음 로그인 전까지 등록에 없으므로, 새 카드는 기록의 값을 보여야 한다.
- 데모 리셋 때 옛 기록을 비우는 일은 도구와 `readAttrRecord` 만 한다 → 카드도 `readAttrRecord` 로 읽는다.
- "모두 지우기" 는 IndexedDB 만 지운다 — 속성 기록(localStorage)은 **지금도 남는다**.
- `/attr.html` 은 화면 모드를 늦게 안다(localStorage·`reset.json`) → 처음 여는 브라우저에서는 salt 칸이 잠깐 보인다.

## 2. 설계
### 2.1 "내 속성" 카드 (`#attrCard`, /user 를 연 뒤)
- 칸은 `attrSchema` 로 만든다(int 입력·enum select·미사용 칸은 없음 — `renderAttrsForm` 과 같은 규칙, 값 칸은 따로 둔다: 신원 카드의 칸은 2초마다 덮인다). "저장" 버튼 하나.
- 보이는 값: 저장한 기록이 있으면 그것, 없으면 등록된 값. 상태 한 줄: "넣지 않음" / "저장됨 — 다음 로그인부터 반영" / "반영됨". 편집 중인 칸은 새로고침이 덮지 않는다.
- 스스로 넣은 값이고 누구도 보증하지 않는다는 한 줄을 둔다(기존 문구 재사용).

### 2.2 저장
- 코어 새 동작 `wrapperAttrRecord({ profile })`(래퍼만, 그 밖은 409): 형식 검사(`encodeProfile` `allowEmptyRequired:false`)를 **패스키를 묻기 전에** 하고, `withSalt` 안에서 `saltNow` → `auidOf`·`attrCommit`. 돌려주는 것은 `{ auid, attrs, commit, profile, schema }` — **salt 는 돌려주지 않는다.** 등록이 없어도 된다(첫 로그인이 이 속성으로 등록한다).
- 화면이 그것을 `mode3_attr_tool_v1`(version 6, 같은 칸)에 쓴다. 쓰기 **전에** `readAttrRecord` 로 데모 리셋 표시를 맞춘다 — 순서가 바뀌면 처음 보는 리셋이 방금 쓴 기록을 지운다. 패스키는 한 번. 취소·오류면 기록을 바꾸지 않고 사유를 카드에 보인다.
- 안내: 바뀌었으면 "저장했습니다 — 다음 로그인부터 반영됩니다. 속성을 바꾸면 다음 로그인 때 사용자 자격증명이 바뀌어 지금 열린 서비스 세션은 끝납니다." 첫 등록 전이면 뒤 문장을 빼고, 등록된 값과 같으면 "바뀐 것이 없습니다".

### 2.3 salt 가 나오는 길을 닫는다 (래퍼만)
- 코어 `showSalt` 는 래퍼에서 409 `salt_hidden` — 화면만 숨기지 않는다. "salt 보기" 버튼·대화상자는 래퍼에서 그리지 않는다.
- `/attr.html`: 래퍼 서버가 `<html data-attr-moved="1">` 로 바꿔 낸다(다른 방식의 서버는 파일 그대로). 이 표시가 있으면 입력 폼을 **처음부터** 숨기고, 제출 처리기도 거절한다. 보이는 것: "zkWrapper 에서는 내 세션 관리(/user)에서 속성을 넣습니다" + 링크, 이미 있는 기록(읽기만).

### 2.4 안내 문구 (래퍼 변형만)
`user_wrap_attrs_unset_hint` 링크 → `/user`(새 탭), `attrs_unset`·`attr_record_missing`·`attr_record_salt_mismatch`("이 패스키로 저장한 속성이 아닙니다 — /user 에서 다시 저장")·`user_attr_empty_note`·`attr_*`. 보관 상태 카드로 옮겨 둔 도구 링크(`#pkAttrNote`)는 없앤다. 시연 대본의 속성 장면.

## 3. 한계
- 속성은 지금처럼 이 브라우저 localStorage 에 평문으로 남는다(salt 는 없다).
- 래퍼에서는 salt 를 볼 길이 없어진다 — 백업 카드도 없으므로(같은 날 결정) **패스키가 유일한 열쇠다.**
- 속성을 비우는(되돌리는) 기능은 없다. 기록을 지워도 등록된 속성은 남는다(지금과 같다).
- 조건 서비스의 승인 창은 속성이 없으면 멈춘다. `/user` 에서 저장한 뒤 서비스에서 다시 눌러야 한다.

## 4. 검증
- 코어: 저장이 패스키 한 번·salt 가 응답에 없음·도구의 계산과 같은 `auid`·`commit`(같은 salt·속성의 KAT)·형식 오류는 패스키 0번·복구한 기기(봉투)에서도 같은 salt·래퍼 `showSalt` 409·다른 방식은 그대로.
- 브라우저: `/user` 저장 → 기록 version 6 → **zkTWO 로그인 통과**(attrs_unset 아님); 등록 전 저장 → 첫 로그인이 그 속성으로; 저장 뒤 새로고침해도 값이 남음; 취소하면 기록 그대로; 바꾸면 zkONE 세션이 끝나고 안내와 같음.
- salt 가 DOM·localStorage·sessionStorage·IndexedDB·클립보드 어디에도 없음(저장 전후). `/attr.html` 은 입력 칸이 처음부터 안 보이고 제출해도 거절.
- 기존 사례(170·180·403·838행 근처)를 새 흐름으로. `test_mode3_demo_strings`. 도구 자체의 테스트(다른 방식)는 고치지 않는다.
- 라이브: `/user` 저장 → zkTWO 로그인. 5100 은 **재시작이 필요하다**(`/attr.html` 을 서버가 바꿔 낸다) — 먼저 묻는다.

## 5. 정한 것 (2026-11-25)
- **Q1.** "내 속성" 카드를 "연결된 서비스" 다음에 둔다. **Q2.** 래퍼의 "모두 지우기" 는 속성 기록도 지운다. **Q3.** `/attr.html` 은 래퍼 서버가 표시를 붙여 낸다(표시를 못 붙이면 500 — 입력 칸을 내지 않는다).
