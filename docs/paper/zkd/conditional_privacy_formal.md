# zk-Delegation의 조건부 프라이버시(Conditional Privacy): 형식 정의와 증명

작성 2026-09-18. 대상은 논문 v3(`2026-09-18_v3_zk-Delegation_research_article.docx`)의 프로토콜이며, 그 §V-E(관계 R, Table 2)·§V-G(개봉)·§VII-C(체인 채널)를 전제로 한다. 목표는 논문 VII장의 비형식 논증 중 "조건부 추적 가능성"에 해당하는 부분을 게임 기반 정의와 귀착(reduction) 증명으로 바꾸는 것이다.

## 0. 요약

조건부 프라이버시는 네 성질의 결합이다.

1. **단일 당사자 익명성.** 서비스(체인을 읽는 누구든 포함)는 혼자서 세션이나 트랜잭션을 사용자에 연결하지 못한다. AA(체인을 읽는 AA 포함)는 발급 창 단위의 익명 집합(크기 n) 안에서 균일 추측 이상으로는 좁히지 못한다.
2. **협력 추적 가능성.** 서비스와 AA가 절차대로 협력하면 그 세션의 사용자가 정확히 열린다.
3. **무고 불가능(soundness).** 검증을 통과한 트랜스크립트는 그 성명 안의 신원 외의 다른 사용자로 열리지 않는다.
4. **개봉 국소성.** 한 세션을 열어도 다른 세션은 열리지 않는다.

정리 1–5가 이 넷을 각각 CDH(랜덤 오라클 모델), Groth16의 지식 건전성과 영지식성, Pedersen 커밋의 결합성·은닉성, EdDSA의 위조 불가능성으로 귀착시킨다. AA 측 익명성만은 조건 없는 정의에 1/n 항이 남는다(정리 3).

## 1. 설정과 표기

- **군.** 𝔾 = ⟨B8⟩는 Baby Jubjub의 소수 위수 부분군, 위수 ℓ (2^250 < ℓ < 2^251). 스칼라는 [0, 2^250)에서 뽑는다. 𝔽는 BN254 스칼라체.
- **해시.** H = Poseidon. 증명에서는 H를 랜덤 오라클(RO)로 모델한다.
- **사용자.** u ↦ (uid_u, s_u), s_u ← [0, 2^250) 균일. 등록 커밋 cm_u = s_u·G₃ + r_u·H₀ (H₀는 Pedersen의 블라인딩 생성원; 논문의 H).
- **서비스.** s ↦ arid_s. 트레이스 키 조각 x_S (서비스), x_A (AA), 결합 키 pk_T = (x_S + x_A)·B8.
- **태그.** 평문 h = H(uid, arid) ∈ 𝔽. Enc(pk_T, h; r) = (c1, c2) = (r·B8, h + H(r·pk_T)), r ← [1, 2^250). 부분 복호 PD(x, c1) = x·c1. 결합 Dec(c2, D_S, D_A) = c2 − H(D_S + D_A).
- **트랜스크립트.** T = (pub, π), pub = (PPID, arid, pk_i, max_height, chainid, allowAgent, root, pk_A, pk_T, c1, c2). π는 관계 R(논문 Table 2, 조건 1–6)에 대한 Groth16 논증. 온체인 트랜잭션의 calldata는 같은 (pub, π)를 담는다.
- **검증.** Vf(T) = Groth16.Verify(vk, pub, π) ∧ (pk_A, pk_T, arid, chainid가 검증자의 고정값과 일치) ∧ (root가 현재 root) ∧ (head ≤ max_height) ∧ (allowAgent ∈ {0,1}) ∧ (c1 ≠ O). 서비스와 컨트랙트가 같은 술어를 쓴다(논문 §V-I).
- **개봉.** Open(T): 서비스가 D_S = PD(x_S, c1)을 서명해 보내고, AA가 Vf(T)와 서명·신선도를 확인한 뒤 운영자 승인 아래 D_A = PD(x_A, c1), h = Dec(c2, D_S, D_A), uid = Resolve(h, arid)를 계산한다. Resolve는 등록부에서 H(uid, arid) = h인 uid를 찾는다(H의 충돌 저항성으로 유일).
- **운영자.** 승인은 절차적 통제다. 형식 모델에서는 "AA의 부분 복호는 서비스의 부분 복호와 유효한 트랜스크립트가 있을 때만 계산된다"는 오라클 O_open으로만 나타낸다.

## 2. 가정

- **(A1) CDH.** 𝔾에서 (a·B8, b·B8)로부터 ab·B8을 계산하는 것이 어렵다. Adv^CDH(B)로 표기.
- **(A2) RO.** H는 랜덤 오라클이다. 질의 수 q_H.
- **(A3) Groth16.** 지식 건전성(추출기 Ext가 Vf를 통과한 π에서 R의 증인을 뽑는다, 실패 확률 ε_KS)과 영지식성(시뮬레이터 Sim이 증인 없이 구별 불가능한 π를 만든다, 이점 ε_ZK).
- **(A4) Pedersen.** 결합성(DL 가정)과 은닉성(블라인딩이 250비트 구간이라 계산적, 구간 DL 가정).
- **(A5) EdDSA.** σ_AA는 선택 메시지 공격에 위조 불가능(EUF-CMA).
- **(A6) 모델.** AA와 서비스는 honest-but-curious. 서비스와 AA가 절차 밖에서 조각을 합치는 것은 범위 밖(논문 §III-B). AA가 x_A를 정직하게 갖지 않는 것은 (A7)로 배제한다.
- **(A7) 조각 PoK.** 등록 승인 때 AA는 PoK{x_A : X_A = x_A·B8}(Schnorr, Fiat–Shamir, 챌린지가 (arid, X_S, X_A)를 덮음)을 내고 서비스는 pk_T = X_S + X_A와 이 증명을 검증한다. RO 모델에서 이 증명은 지식 건전하다(추출기가 x_A를 뽑는다). 구현: lib/mode3_trace.js proveShare/verifyShare (2026-09-21).

## 3. 정의

### 정의 1 (한 조각에 대한 태그 익명성, 개봉 오라클 포함)

역할 role ∈ {S, A}. 게임 TAG-ANON^b_{role}(𝒜):

1. 도전자가 x_S, x_A ← ℤ_ℓ를 뽑고 pk_T를 계산한다. 𝒜에게 pk_T와 x_role을 준다(𝒜는 그 역할의 당사자다).
2. 𝒜는 개봉 오라클 O_open(T)를 부를 수 있다: Vf(T) = 1이고 T ≠ T*이면 h = Dec(c2, PD(x_S, c1), PD(x_A, c1))을 돌려준다.
3. 𝒜가 h₀, h₁ ∈ 𝔽를 낸다. 도전자가 T* ← 정직하게 생성된 트랜스크립트로서 태그가 Enc(pk_T, h_b; r*)인 것(π는 관계 R에 대한 유효 논증)을 준다.
4. 𝒜가 b′를 낸다. Adv^{TAG}_{role}(𝒜) = |Pr[b′ = b] − 1/2|.

### 정의 2 (서비스 측 세션 익명성; 체인 관찰자 포함)

𝒜는 모든 서비스를 통제하고(x_S들을 안다) 체인 전체를 읽는다. AA는 정직하고 x_A는 비밀이다. 도전 컨텍스트 (chainid*, arid*)를 𝒜가 고른다.

1. 𝒜는 등록된 사용자 집합 U 중 임의의 u와 임의의 (chainid, arid) ≠ (chainid*, arid*)에 대해 정직한 로그인 트랜스크립트를 요청할 수 있다(교차 서비스·교차 체인 연결 불가능성, 논문 G3).
2. 𝒜가 u₀, u₁ ∈ U와 공통의 AA 속성(max_height, allowAgent)을 낸다. 도전자가 u_b의 (chainid*, arid*)에서의 트랜스크립트 T*를 정직하게 만들어 준다(세션키는 새로).
3. 이후에도 1의 요청은 허용하되 (chainid*, arid*)에서 u₀, u₁의 트랜스크립트는 주지 않는다(PPID는 같은 컨텍스트의 세션을 의도적으로 잇는다).
4. 𝒜가 b′를 낸다. Adv^{S-ANON}(𝒜) = |Pr[b′ = b] − 1/2|.

### 정의 3 (AA 측 세션 익명성; 체인 채널 포함, G4의 강화)

𝒜는 AA다: 모든 등록 정보(uid, pk_u, cm_u), 모든 발급 요청 (uid, C_pt, chainid, allowAgent, π_issue, sig_u)과 발급 기록, x_A를 알고 체인 전체를 읽는다. 서비스는 정직하고 x_S는 비밀이다. 조건은 두지 않는다: 𝒜가 어떤 사용자들을 언제 발급받게 할지 전부 고른다.

1. 𝒜가 등록 사용자들에게 발급을 요청하게 한다(횟수·시점·chainid·allowAgent 모두 𝒜의 선택). 도전자는 정직한 AA로서 발급하고, 𝒜는 발급 요청 전부를 본다. 발급 기록의 집합을 I라 한다.
2. 도전자가 I에서 기록 i* ← I를 균일하게 뽑아, 그 성명으로 온체인 트랜잭션 T*(pub, π, 계정 주소, calldata)를 만들어 𝒜에게 준다.
3. 𝒜가 i′ ∈ I를 낸다. 𝒜가 이기는 것은 i′ = i*.

T*의 공개 입력 중 AA가 발급 때 본 값은 (chainid, allowAgent, max_height)뿐이다. 이 삼중항이 T*와 같은 발급 기록의 집합을 W(T*) ⊆ I, 그 크기를 n = |W(T*)|이라 하자(양자화 때문에 한 창 안의 발급은 같은 max_height를 갖는다). 𝒜의 이점을

Adv^{A-ANON}(𝒜) = Pr[i′ = i*] − E[1/n]

으로 정의한다. 즉 "AA가 볼 수 있는 값으로 좁힌 집합 안에서 균일 추측하는 것"보다 얼마나 더 잘하느냐가 이점이다. n은 프로토콜 파라미터가 아니라 배포의 성질(창당 발급 수)이며, 정리 3은 이점이 무시할 수 있음을, 곧 AA의 성공 확률이 1/n을 넘지 못함을 말한다.

### 정의 4 (추적 가능성)

- **(4a) 정확성.** 등록 사용자 u가 서비스 s에서 정직하게 만든 트랜스크립트 T에 대해 Open(T) = uid_u.
- **(4b) 건전성(무고 불가능·결합).** 어떤 PPT 지갑 𝒜도, Vf(T) = 1이면서 Open(T) ≠ uid′인 T를 무시할 수 없는 확률로 내지 못한다. 여기서 uid′는 T의 π에서 Ext가 뽑은 증인의 uid, 즉 그 성명의 커밋 C_pt에 들어 있고 AA가 서명 전에 π_issue로 확인한 신원이다.
- **(4c) 2-of-2 필요성.** x_S, x_A 중 하나 이하만 아는 PPT 𝒜는 정직한 T의 h를 무시할 수 없는 확률로 계산하지 못한다.

### 정의 5 (개봉 국소성)

정의 1의 게임에서 O_open이 허용된다는 사실 자체가 국소성이다: T* 외의 어떤 트랜스크립트를 열어 주어도 T*는 열리지 않는다.

**조건부 프라이버시**는 정의 2, 3, 4, 5를 모두 만족하는 것이다.

## 4. 정리와 증명

### 정리 1 (한 조각 태그 익명성, 개봉 오라클 포함)

(A1)–(A3) 아래, role ∈ {S, A}인 모든 PPT 𝒜에 대해

Adv^{TAG}_{role}(𝒜) ≤ q_H · Adv^{CDH}(B) + q_O · ε_KS + q_O · 2^{−250}.

여기서 q_O는 개봉 오라클 질의 수이다.

**증명.** CDH 인스턴스 (X, Y) = (a·B8, b·B8)를 받은 귀착 B를 만든다. B는 𝒜의 역할이 아닌 쪽의 조각 공개값을 X로 둔다(즉 role = S면 X_A := X, role = A면 X_S := X), 자기 쪽 조각 x_role ← ℤ_ℓ를 뽑아 𝒜에게 주고, pk_T = X + x_role·B8을 준다. B는 a를 모른다.

*도전.* B는 c1* := Y (즉 r* = b, 미지), c2* := h_b + z (z ← 𝔽 균일)로 두고, π는 Sim으로 만든다(ZK). 정직한 태그에서는 c2* = h_b + H(K*) with K* = r*·pk_T = b·X + x_role·Y = ab·B8 + x_role·Y이다. 𝒜가 H를 K*에서 질의하지 않는 한 z는 H(K*)와 완벽히 같은 분포이므로 𝒜의 관점은 실제 게임과 동일하고, 그때 c2*는 h_b와 독립인 균일 값이라 b에 대한 정보가 없다. 따라서 𝒜의 이점은 전부 "H를 K*에서 질의하는 사건" E에 들어 있다. B는 𝒜의 RO 질의 중 하나 Q를 균일하게 골라 Q − x_role·Y를 CDH 답으로 출력한다. E가 일어나면 확률 1/q_H로 올바른 질의를 고르므로 Pr[E] ≤ q_H · Adv^{CDH}(B).

*개봉 오라클.* T ≠ T*, Vf(T) = 1인 질의에 B는 Ext를 돌려 증인 (uid, r, …)를 얻는다(실패 확률 ε_KS). 조건 5가 c2 = H(uid, arid) + H(r·pk_T)를 강제하므로 h = H(uid, arid)를 RO 표에서 읽어 답하면 실제 오라클과 같다. 예외는 T의 c1이 c1* = Y와 같은 경우인데, 그러면 Ext가 r = b를 뽑아 B가 DL을 풀게 되므로(CDH보다 강함) 이 경우도 B는 답을 낼 수 있다. 추출된 r이 [1, 2^250) 밖이거나 c1 ≠ r·B8이면 R 위반이라 Vf가 거절했어야 하므로 일어나지 않는다. 남는 오차는 질의당 ε_KS와 RO 충돌 2^{−250}. □

### 정리 2 (서비스 측 세션 익명성)

(A1)–(A4) 아래

Adv^{S-ANON}(𝒜) ≤ 2·ε_ZK + Adv^{TAG}_{S}(𝒜′) + q_H · 2^{−250} + negl.

**증명.** 혼합 논증.

- **H₀:** 실제 게임, b = 0. **H₃:** 실제 게임, b = 1.
- **H₁:** H₀에서 T*의 π를 Sim(pub)로 바꾼다. 구별 이점 ≤ ε_ZK. 이제 π는 증인과 독립이다.
- **H₂:** H₁에서 태그 (c1, c2)를 Enc(pk_T, H(uid_{u₁}, arid*))로 바꾼다. 𝒜는 x_S를 알고 x_A는 모르므로 이것은 정확히 정의 1의 role = S 게임이고, 구별 이점 ≤ Adv^{TAG}_{S}. 𝒜가 1·3단계에서 얻는 다른 컨텍스트의 트랜스크립트는 pk_T′ ≠ pk_T (서비스마다 다른 결합 키) 아래의 태그라 B가 자기 조각으로 만들 수 있다.
- **H₂ → H₃:** 남은 차이는 PPID와 pk_i다. pk_i는 새로 뽑은 세션키라 b와 독립. PPID = H(uid_{u_b}, s_{u_b}, chainid*, arid*)는 RO 출력이며 𝒜는 s_{u_b}를 모른다. 𝒜가 H를 (uid, s, chainid*, arid*)에서 질의해 맞힐 확률은 s_u가 250비트 균일이라 q_H · 2^{−250} 이하이고, 그 사건이 없으면 PPID는 u₀·u₁ 어느 쪽에 대해서도 균일 독립 값이다. 다른 컨텍스트의 PPID′ = H(uid, s_u, chainid′, arid′)는 서로 다른 RO 입력이라 정보를 주지 않는다(G3의 내용). 따라서 H₂와 H₃는 q_H · 2^{−250} 안에서 동일.

이점을 더하면 주장의 상한. max_height와 allowAgent는 정의에서 공통으로 고정했고 chainid*, arid*, root, pk_A, pk_T는 사용자와 무관하다. □

### 정리 3 (AA 측 세션 익명성, 체인 채널 포함)

(A1)–(A4) 아래

Pr[i′ = i*] ≤ E[1/n] + (n_max − 1)·ε₂,  즉 Adv^{A-ANON}(𝒜) ≤ (n_max − 1)·ε₂,

여기서 n_max는 I의 가장 큰 클래스 크기이고

ε₂ = 2·ε_ZK + 2·ε_ZK^{issue} + 2·Adv^{hide}(B₁) + Adv^{TAG}_{A}(𝒜′) + q_H · 2^{−250}

은 같은 클래스에 속한 두 기록을 구별하는 이점의 상한이다. ε_ZK^{issue}는 π_issue(시그마 프로토콜)의 영지식성, Adv^{hide}는 Pedersen 커밋 C_pt의 은닉성(구간 DL) 이점이다.

**증명.** 두 단계다.

*(i) 클래스 밖은 자명, 클래스 안은 계산적으로 동일.* T*의 pub에서 𝒜가 발급 기록과 대조할 수 있는 값은 (chainid, allowAgent, max_height)이고, 이것은 W(T*)를 정확히 결정한다. 그 밖의 값이 W(T*) 안의 어느 기록에서 왔는지에 대해 계산적으로 독립임을 보이면, 𝒜의 최선은 W(T*) 안에서의 추측이다.

*(ii) 같은 클래스의 두 기록 i₀, i₁ ∈ W(T*)에 대한 구별 불가능성.* AA의 뷰는 두 발급 요청 (uid_j, C_pt^{(j)}, chainid, allowAgent, π_issue^{(j)}, sig_u^{(j)}), T* = (pub, π), 계정 주소, x_A, 등록부다. 혼합:

- π와 π_issue를 시뮬레이터로 바꾼다(2·ε_ZK + 2·ε_ZK^{issue}). 이제 사용자에 의존하는 것은 uid_j(AA가 원래 아는 값), C_pt^{(j)}, sig_u^{(j)}, 그리고 T*의 PPID, 계정 주소, 태그다.
- pub에는 C도 C_pt도 없다(조건 2·4는 회로 안). 𝒜가 C_pt^{(j)}와 T*를 이으려면 T*의 값에서 C_pt^{(j)}의 내용(arid, s_u, pk_i, 속성)을 알아내야 한다. pub의 pk_i는 C_pt 안의 pk_i와 같은 값이지만, 𝒜가 C_pt에서 pk_i를 읽을 수 있으면 커밋 은닉성이 깨진다: 두 후보 중 어느 것이 C_pt^{(j)}에 있는지 맞히는 것이 곧 은닉성 게임이다(2·Adv^{hide}). sig_u^{(j)}는 C_pt 위 서명이라 C_pt 이상의 정보를 주지 않는다.
- 태그: 𝒜는 x_A를 알고 x_S를 모르므로 정의 1의 role = A(Adv^{TAG}_{A}).
- PPID: 𝒜는 uid_j를 알지만 s_{u_j}는 모른다(cm_u는 은닉 커밋이라 s_u를 주지 않으며, 그 은닉성은 위 Adv^{hide}에 포함된다). RO 질의로 맞힐 확률 q_H · 2^{−250}. 계정 주소는 PPID의 결정적 함수라 추가 정보가 없다.
- max_height, chainid, allowAgent: 같은 클래스라 동일. root, pk_A, pk_T: 사용자와 무관.

따라서 같은 클래스의 두 기록에 대한 뷰는 ε₂ 안에서 구별 불가능하다.

*(iii) 추측 확률.* T*의 뷰가 W(T*) 안의 n개 기록에 대해 쌍마다 ε₂ 안에서 동일하므로, 표준 논증(균일한 i*에 대해 뷰를 i*에서 클래스의 기준 기록으로 바꾸는 혼합)으로 Pr[i′ = i*] ≤ 1/n + (n − 1)·ε₂이고, I 전체에 대해 기대값을 취하면 주장이 따른다. □

**해석.** 양자화가 하는 일은 n을 1보다 크게 만드는 것이다. (2026-09-18 갱신: 양자화는 AA 가 아니라 지갑이 한다 — max_height 는 지갑이 ⌈(head+T)/G⌉·G 로 고르고 AA 는 그대로 서명하며 검증자가 상한 L 을 강제한다. 정리의 n 은 같은 max_height 로 발급을 요청한 기록의 수이므로 진술은 그대로이고, 그리드를 무시한 지갑은 자기 자신만 n=1 인 클래스에 넣는다.) 창이 없으면(G = 1) max_height가 발급 높이를 그대로 드러내 한 블록에 발급된 기록만 같은 클래스에 들어가 n이 사실상 1이 되고, 정리 3은 참이지만 내용이 없다. 창 G가 넓을수록 n이 커지고, 그 대가는 만료 정밀도다(논문 §VII-C). 정리는 "AA는 창 단위 익명 집합 이상으로는 좁히지 못한다"를 말하지, 익명성이 계산적으로 완전하다고 말하지 않는다.

**주석 (2026-09-22, 속성 선택 공개 V6).** pub 에 공개 술어 9개(disc_mask, disc_lo[4], disc_hi[4]; 회로 조건 7 — mask 비트가 1 인 슬롯 k 에 대해 disc_lo_k ≤ a_k ≤ disc_hi_k)가 더해졌고, 속성 a 는 이제 사용자 선택이 아니라 **AA 계정 기록**이다(π_issue V2 가 C_pt 의 속성이 AA 기록과 같음을 강제). 따라서 정의 3 에서 "T* 의 공개 입력 중 AA 가 대조할 수 있는 값"은 (chainid, allowAgent, max_height) 에 [14..22] 가 더해지고, AA 는 모든 사용자의 a 를 알므로 클래스 W(T*) 를 **술어를 만족하는 기록**으로 한 번 더 걸러낼 수 있다. 정리 3 의 n 은 n′ = |{ i ∈ W(T*) : a^{(i)} 가 (disc_mask, disc_lo, disc_hi) 를 만족 }|, 즉 "같은 창 안에서 공개된 술어를 만족하는 사용자 수"로 바뀐다; 상한은 E[1/n′] + (n′_max − 1)·ε₂ 로 형태가 같다(같은 클래스의 두 기록은 같은 술어를 만족하므로 [14..22] 가 둘을 구별하지 않고, 나머지 항은 (ii) 그대로). mask = 0(로그인·공개 없는 트랜잭션)이면 n′ = n 이다. 정확한 값 공개(lo = hi)는 n′ 를 그 값을 가진 창 안 사용자 수로, 구간 공개는 구간 안 사용자 수로 줄인다 — 술어가 좁을수록 익명 집합이 작다. 이것이 논문 §VII-D 가 G5 를 "속성 사용처 비관측"으로 재정의하면서 §IX 에 적은 "공개 값에 의한 익명 집합 축소" 한계다(보안 형식 문서 §4.5 정리 5′·§8 (d)). 서비스 측(정의 2·정리 2)은 영향이 없다: 공개된 구간은 사용자가 고른 공개이고, 비공개 슬롯은 hiding + ZK 로 숨는다.

### 정리 4 (추적 가능성)

(A1)–(A5) 아래 정의 4의 (4a)(4b)(4c)가 성립한다.

**증명.**
- **(4a)** D_S + D_A = x_S·c1 + x_A·c1 = (x_S + x_A)·r·B8 = r·pk_T이므로 Dec(c2, D_S, D_A) = c2 − H(r·pk_T) = H(uid_u, arid). Resolve는 등록부에서 H(uid, arid) = H(uid_u, arid)인 uid를 찾는데, H의 충돌 저항성(RO) 아래 uid_u가 유일하다.
- **(4b)** Vf(T) = 1이라 하자. Ext로 증인 (uid, s_u, blind, a, σ_AA, r, path)을 뽑는다(실패 ε_KS). 조건 5는 c2 = H(uid, arid) + H(r·pk_T), c1 = r·B8을 강제하므로 Open(T)는 H(uid, arid)를 얻고 Resolve는 uid를 돌려준다(uid가 등록부에 없으면 "해당 없음"이지, 다른 사용자가 아니다). 즉 Open(T) ∈ {uid, ⊥}. 이 uid가 "그 성명의 신원"인 이유: 조건 1은 C = H(C_pt)에 대한 AA 서명을 검증하고, 조건 2는 C_pt가 같은 uid로 열림을 강제한다. AA는 π_issue가 uid′ ∈ C_pt를 증명한 뒤에만 C에 서명하므로, (A5)에 의해 C는 AA가 서명한 어떤 등록 uid′의 커밋이고, (A4)의 결합성에 의해 같은 C_pt를 uid ≠ uid′로 여는 증인은 없다. 따라서 uid = uid′이고 ⊥는 등록 삭제 같은 절차적 사유 외에는 발생하지 않는다. 무고, 즉 다른 등록 사용자로 열리는 사건은 Ext 실패·서명 위조·결합성 위반 중 하나를 요구하므로 무시할 수 있다.
- **(4c)** h를 계산하는 𝒜는 h₀ ≠ h₁ 중 어느 것이 암호화됐는지 구별할 수 있으므로 정의 1을 깬다. 정리 1에서 이점은 무시할 수 있다. □

## 5. 프로토콜이 보장하지 않는 것(정의에 반영된 경계)

- **운영자 승인**은 (A6)의 오라클 O_open으로만 모델된다. 암호학이 보장하는 것은 2-of-2까지이고, "승인 없이는 안 열린다"는 AA 운영 절차의 몫이다(논문 §IX).
- **절차 밖 담합.** 서비스와 AA가 x_S + x_A를 합치면 모든 태그가 열린다. 정의 1의 게임은 한 조각만 주므로 이 경우를 다루지 않는다. 완화는 x_A를 제3자와 나누는 것(태그 형식 불변).
- **악의적 AA의 키 선택(2026-09-21 닫힘).** AA가 X_S를 무시하고 pk_T′ = x′·B8을 인증하거나 X_A = X′ − X_S로 골라 pk_T의 비밀을 혼자 아는 rogue key는, 서비스가 pk_T = X_S + X_A와 (A7)의 PoK를 검증하므로 배제된다: X_A = X′ − X_S에 대한 증인 x_A를 AA는 모른다(알면 x_S를 알게 되어 DL을 깬다). 따라서 (4c)는 honest-but-curious 가정 없이 (A1)·(A2)·(A7) 아래 성립한다. 남는 것은 절차 밖 담합(위)과 조각 유실(어느 한 조각을 잃으면 그 서비스의 과거 태그는 영구히 열리지 않는다 — 가용성 한계, 논문 §IX)뿐이다.
- **익명 집합.** 정리 3의 상한 1/n에서 n은 배포의 성질(창당 발급 수)이다. 작은 배포에서는 n = 1일 수 있고, 그때 AA는 트랜잭션을 발급 기록 하나로 특정한다. 이것은 계산적 항으로 사라지지 않으며, 창 G를 넓혀서만 완화된다.
- **시각 상관.** 발급 직후에 나타난 트랜잭션이라는 통계적 단서는 정의 3에 없다(도전자가 시각을 통제하지 않는다). 논문 §VII-C·§IX에 한계로 적혀 있다.
- **(d) 공개 값에 의한 익명 집합 축소(2026-09-22).** 트랜잭션이 속성 구간을 공개하면 정리 3 의 n 이 n′(창 ∩ 술어 만족 집합, 정리 3 주석)으로 줄고, 공개 값은 체인에 영구히 남아 PPID·서비스에 묶인다. 정확한 값 공개가 구간 공개보다 더 줄인다. 이는 계산적 항이 아니라 사용자가 고른 공개의 정보량이며, 구간을 넓게 잡는 것만이 완화다.
- **(e) 데모 API(2026-09-22).** 지갑이 속성을 다시 받는 `/cia/attrs` 는 sig_u 만 검사하고 nonce 신선도를 검사하지 않아 요청 재생으로 같은 속성을 다시 읽을 수 있다; 서비스의 `/api/mode3/sessions`·`/api/mode3/logins` 는 인증 없는 데모 API 이고 공개된 구간(`disclosure`)까지 노출한다. 둘 다 정의 1–5 의 게임 밖(정직한 당사자의 구현 경계)이며 데모 범위의 한계다.

**주석 (2026-09-23, 자격증명 이중 구조 C_u/C_s).** §1 의 "성명" 은 이제 두 커밋으로 읽는다: 사용자당 하나의 C_u = uid·G₁ + s_u·G₃ + Σa_k·G_{4+k} + blind_u·H₀(AA 가 π_u 로 한 번 검증, Cf_u = H(C_u)), 로그인마다 C_s = arid·G₂ + pk_i·G₄ + blind_s·H₀(무증명, Cf_s = H(C_s)), σ_AA = Sign_AA(H(D_cred, Cf_u, Cf_s, max_height, chainid, allowAgent)). 관계 R 의 조건 2 는 C_u 를 증인으로, C_s 를 **공개** arid·pk_i 로 재계산하고, 조건 4 의 리프는 H(4, Cf_u) 다. 정의 3 의 AA 뷰는 (uid, C_u, π_u) 한 번과 발급 요청 (uid, Cf_u, C_s, chainid, allowAgent, max_height, sig_u) 이며, AA 가 발급 기록을 남기지 않으므로 집합 I 는 𝒜 가 관측 시점에 스스로 적는 것으로 정의한다(게임에는 영향 없음 — 𝒜 는 어차피 요청 전부를 본다). 정리 3 의 혼합 (ii) 는 다음과 같이 바뀐다: ε_ZK^{issue} 는 π_u 의 HVZK(사용자당 한 번이라 기록 쌍 i₀, i₁ 에 대해 각 1회), Adv^{hide} 는 C_s 의 은닉성(arid·pk_i 가 C_s 안) — pub 의 pk_i 를 C_s^{(j)} 와 잇는 것이 곧 은닉성 게임이라는 논증은 C_pt 때와 같다. C_u^{(j)} 는 uid_j 별 고정값이고 AA 는 uid_j 를 원래 알지만, T* 의 어떤 값도 C_u 로 이어지지 않는다(pub 에 C_u·Cf_u 가 없고, PPID 는 s_u 를 포함한 RO 출력, 리프는 회로 안). 따라서 상한 형태 E[1/n] + (n_max − 1)·ε₂ 는 그대로이고 n 은 V6 주석의 n′ 이다. 정리 4(4b) 의 논증도 같은 형태로 옮겨진다: 조건 1 은 (Cf_u, Cf_s) 에 대한 AA 서명을, 조건 2 는 C_u 가 같은 uid 로 열림을 강제하고, AA 는 π_u 가 uid′ ∈ C_u 를 증명한 Cf_u 만 서명하므로(A5), (A4) 결합성 아래 uid = uid′ 다. 폐기 리프가 자격증명 단위라는 점은 정의 2·3 에 영향이 없다(리프는 트랜스크립트에 나타나지 않는다).
