# Mode 3 시연 순서 한 장 (snap 모드 · VM 분리 데모)

2026-11-14. 발표자가 따라가는 순서만 적는다 — 어느 탭에서 무엇을 누르고, 어디서 다시 로그인해야 하는지.
단계별 확인 포인트(어느 창이 떠야 하는지)는 `docs/MODE3_DEMO.md` 의 "수동 체크리스트(`snap` 모드)" S0~S18 이 정본이다.
이 순서는 코드와 격리 스택 화면을 근거로 썼고, **실제 MetaMask Flask 로 처음부터 끝까지 리허설해 확인한 것은 아니다.**

## 탭 — 이 순서로 열어 둔다

| # | 화면 | 주소 | 누구의 화면 |
|---|---|---|---|
| 1 | zk 스냅 화면 | `http://localhost:5100` | 사용자(스냅) |
| 2 | 속성 도구 | `http://localhost:5100/attr.html` | 사용자(브라우저 안에서만 계산) |
| 3 | zkIdP 내 계정 | `http://localhost:4100/user` | 사용자가 보는 IdP |
| 4 | zkIdP 관리자 | `http://localhost:4100/admin` | IdP |
| 5 | zkONE | `http://localhost:3100` (관리자 `/admin`) | 서비스 1 — 조건 없음 |
| 6 | zkTWO | `http://localhost:3101` (관리자 `/admin`) | 서비스 2 — 국가(한국·일본)·만 19세 이상 |

상단 바는 zk 스냅·zkIdP·zkONE 이 같은 남색이고 zkTWO 만 초록이다. 탭을 옮길 때마다 "지금은 zkIdP 화면", "지금은 서비스 화면" 이라고 말로 짚는다.
화면이 1920×1080 이면 브라우저를 125~150% 로 확대한다 — 내용 폭이 고정이라 확대하지 않으면 글자가 작다(1280 폭까지는 배치가 그대로다).
관리자 비밀번호는 `scripts/demo_split_start.sh` 상단 주석의 `ADMIN_OPEN` 줄에 있다.
salt 를 복사할 때 잠깐 화면에 보인다. 화면을 공유하고 있다면 복사한 뒤 바로 "비밀 값 가리기" 를 누른다(속성 도구의 salt 칸은 가려져 있다).

## 전날까지

1. 기동: `AUTO_APPROVE=1 TTL_BLOCKS=30 bash scripts/demo_split_snap_reset.sh` (코드를 고쳤으면 앞에 `SYNC=1`).
   - `AUTO_APPROVE=1`: zkONE·zkTWO 승인을 건너뛴다. RP 등록·승인을 보여 줄 때만 뺀다(`docs/MODE3_DEMO.md` "시연 순서(2026-10-22)" 1~2).
   - `TTL_BLOCKS=30`: 기본 5 는 세션이 몇 블록 만에 만료된다(자연 만료 시연용). Race (2) 를 하려면 늘린다.
   - 이 스크립트는 스냅 에이전트(:5100)·스냅 서버(:8082)·체인·VM 의 서버를 모두 내렸다 다시 띄운다.
2. MetaMask Flask 에 스냅 0.5.1 을 설치하고(1번 탭 "MetaMask 연결") "새로 만들기" → 백업 비밀번호 두 번 → "백업 파일 저장".
   - 백업 파일과 비밀번호를 손 닿는 곳에 둔다. 스냅을 MetaMask 에서 지우면 salt 가 지워지고, 되살릴 길은 이 백업뿐이다.
   - 파일 저장 창은 다운로드 폴더를 그대로 보여 준다. 화면을 공유한다면 저장 위치를 빈 폴더로 바꿔 둔다.
3. 처음부터 끝까지 한 번 돌려 본다. 로그인 한 번에 걸리는 시간을 재 둔다(이 문서는 재지 않았다).

**리허설을 반복할 때**: 리셋 스크립트를 다시 돌려도 스냅의 salt 는 남는다. 1번 탭 "내 계정" → "스냅 초기화"(등록만 지운다)를 누르고 아래 "본 시연" 1 부터 다시 한다. 스냅을 지우거나 다시 깔 필요가 없다. 같은 salt 이므로 auid 도 같다.

**시연 당일 하지 않는 것**: MetaMask 에서 스냅 삭제, "스냅 업데이트"(salt 가 남는지 실제 MetaMask 로 확인하지 못했다), 스냅 에이전트 재시작(모든 서비스 로그인이 끊긴다).

## 설치 없는 패스키 모드(`passkey-web`)로 할 때 (2026-11-17)

MetaMask·스냅 없이 패스키만 쓰는 모드다(`docs/MODE3_DEMO.md` "설치 없는 패스키 경로"). 시연 순서 S0~S18 은 대체로 그대로이고 달라지는 것은 아래와 같다. **Race (2)(보내기 전에 멈춤) 단계는 이 모드에 없다** — 에이전트 전용(`/wallet/demo/mine`)이라 건너뛴다(스펙 §8 범위 밖). 나머지 다섯은 다음과 같다. 첫째, 기동은 `WALLET_MODE=passkey-web bash scripts/demo_split_start.sh`(처음이면 전날
`bash scripts/zkd_tls_setup.sh` 와 Chrome 재시작)이고 탭 주소는 `https://wallet.zkd.test:5100`(지갑·`/attr.html`)·`https://idp.zkd.test:4100`(zkIdP)·`https://zkone.zkd.test:3100`·`https://zktwo.zkd.test:3101` 이다 —
IP 나 localhost 로 열면 패스키가 안 된다. 둘째, "MetaMask 연결"·스냅 설치·백업 파일 단계 대신 지갑 페이지에서 **패스키 설정**("패스키 만들기" 또는 "이미 있는 패스키 쓰기")을 한다. salt 는 패스키에서 나오며
브라우저에 저장하지 않는다 — 로그인·출금·재검증·"salt 보기" 처럼 salt 가 필요한 동작마다 패스키를 한 번 묻는다(2026-11-20 — 그전에는 10분간 IndexedDB 에 암호화해 보관했다. 속성 도구도 붙여 넣은 salt 를 저장하지 않는다 — 커밋먼트를 계산한 뒤 칸을 비우고 기록에는 그 salt 의 auid 만 둔다). 셋째(2026-11-18), 화면은 지갑 자리를 "zk 스냅" 이 아니라 **"zk 클라이언트"** 라 부르고("스냅" 이라는 말이 화면에 없다), 승인 창에 **승인·거절 버튼이 없다** — 서비스에서 "zkIdP 로 로그인"·출금을 누르면 창이 요약만 보이고 바로 진행한다.
salt 는 지갑 페이지 맨 아래 "보관 상태" 카드의 "salt 보기" 에서 복사한다. 로그인·출금 뒤에는 같은 페이지의 "영지식 증명" 카드에서(zkWrapper 에서는 `/user` 에 있고 처음에 접혀 있으니 **"증명 N개 보기"** 를 눌러 편다 — 한 번 펴 두면 새로 고쳐도 펴져 있다. "시연: 비밀 바꾸기" 카드의 버튼·"트랜잭션 보내기" 의 "공개할 속성 조건" 도 같다) 방금 낸 증명을 "보기" → "검증"(✓) → "값 바꿔 보기" 로 한 칸을 고쳐 다시 "검증"(✗)해 보일 수 있다(출금 증명은 Blockscout 거래 링크).
넷째(2026-11-19), **zkIdP 로그인이 패스키다**: 서비스의 "zkIdP 로 로그인" 은 처음 한 번(등록)만 zkIdP 인증 창에서 아이디·비밀번호·auid 를 묻고, 그 뒤로는 인증 창 없이 **패스키 한 번**으로 끝난다 —
아래 "다시 로그인" 의 "아이디·비밀번호·auid" 단계가 이 모드에는 없다(패스키 창만 뜬다. 출금·재검증도 창마다 패스키를 한 번 묻는다 — 잔액 확인 같은 세션 요청은 묻지 않는다). zkIdP 페이지(3번 탭)도 로그인 카드의 "패스키로 로그인" 으로
들어갈 수 있다(지갑 창이 떴다 닫힌다) — 아이디·비밀번호 로그인도 그대로 된다. `ISSUE_AUTH=code` 로 띄우면 11-18 까지의 순서(로그인마다 인증 창)다.
다섯째(2026-11-19, 2026-11-20 바꿈), **OIDC 와 견주기 — 일반 OIDC 는 Google 이다**: 서비스 로그인 창의 "Google 로 로그인 (일반 OIDC)" 로 들어가면 Google 계정 선택을 거쳐 돌아오고, 서비스 화면의
"Google 이 이 서비스에 알려 준 것" 칸에 받은 ID 토큰의 `iss`(Google)·`sub = uid`(Google 의 사용자 식별자 — zkTWO 에서도 같은 값)·`aud = rid`(이 서비스의 클라이언트 ID)가 찍힌다. 로그아웃하고 "zkIdP 로 로그인" 으로
다시 들어가면 같은 칸이 `iss`(zkIdP)·`sub = auid_s`·`aud = arid_s`·`PPID` 로 바뀐다(zkTWO 는 다른 값). aud 는 앞 17자를 보인다(예: `123456789012-abcd…` — 전체는 마우스를 올리면 나오고 "받은 ID 토큰(JWT) 본문 보기" 에도 있다).
Google 클라이언트 ID 가 있으면 zkIdP 의 "일반 OIDC · 비교용" 버튼은 기본으로 꺼진다 — 실제 Google 이 안 될 때의 예비로 쓰려면 `PLAIN_OIDC=1` 로 띄운다(그 버튼은 zkIdP 동의 화면을 거쳐 `sub = uid`·`aud = rid` 를 보이고,
zkIdP 관리자 화면의 "uid ↔ auid 대응" 표에 "일반 OIDC 에서 본 서비스"(이름·rid)가 찍힌다).
여섯째-가(2026-11-20), **전체 플로우 한 장**: `https://wallet.zkd.test:5100/common/flow.html`(지갑 페이지 "로그인 전체 플로우" 카드의 "한 장 그림으로 보기" 로도 열린다)을 탭 하나로 띄워 둔다 —
윗줄은 일반 OIDC(Google), 아랫줄은 zk-Delegation 을 같은 모양의 순서도로 나란히 보이고, 주체마다 "알게 되는 것 / 모르는 것" 이 아래에 있다. 줄마다 "처음부터 → 다음" 으로 화살표를 하나씩 켜며 설명하고,
화살표를 누르면 그 단계의 설명과(아랫줄은) 걸린 시간이 펴진다. 아랫줄의 값(auid_s·arid_s·PPID, 앞 17자)은 이 브라우저의 가장 최근 "zkIdP 로 로그인" 의 실제 값이다 — 로그인하면 2초 안에 바뀐다.
윗줄의 실제 값은 서비스만 알므로 모양만 보인다(값은 서비스 화면의 "알려 준 것" 칸).
여섯째(2026-11-19), **로그인 전체 플로우**: 지갑 페이지(1번 탭)의 "로그인 전체 플로우" 카드(세션 카드 바로 아래 — 처음에는 접혀 있으니 **"단계 보기"** 를 누른다. 한 번 펴 두면 새로 고쳐도 펴져 있다)가 "zkIdP 로 로그인" 한 번의 단계를 서비스 · zk 클라이언트 · zkIdP 세 줄 위에 순서대로 보인다(로그인 요청 → 서비스 확인 →
패스키로 salt → 체인 읽기 → 난수 → 임시 키 쌍 → 커밋먼트 → 가명 → π_IdP → 발급 요청 ⇄ 서명 → (게시 대기) → π_RP → 서명 → 증명 전달). 단계를 누르면 "무엇을·왜" 가 펴지고, 로그인한 뒤에는
가장 최근 로그인의 실제 값(가명·커밋먼트·PPID — 공개값뿐)과 단계별 걸린 시간이 채워진다. 말할 것: 시간의 대부분은 영지식 증명 둘(π_IdP·π_RP)과 사람이 패스키를 누르는 시간이고, 가명·난수·임시 키는 밀리초 아래다.
일곱째(2026-11-19, 2026-11-20 뺌), **휴대폰 패스키(QR) 선택지는 화면에서 뺐다**: 지갑 페이지 "패스키 설정" 카드의 "패스키를 둘 곳"(이 기기 / 휴대폰 QR)과 그 안내가 없다 — 이 시연 머신(VMware 게스트)에는
블루투스 어댑터가 없어 Chrome 이 QR 연결을 띄우지 못한다(USB 동글을 VM 에 직접 연결하거나, 블루투스가 있는 노트북에서 SSH 터널로 접속해야 한다 — 어느 쪽도 실제 휴대폰으로 확인하지 못했다).
패스키는 Chrome 의 기본 창으로 만든다. 코어·`passkey_store` 의 힌트·transports 처리는 남아 있어, 확인되면 선택지만 다시 넣으면 된다.
여덟째(2026-11-20), **"패스키로 로그인" 이 계정을 스스로 만든다**(스펙 `docs/superpowers/specs/2026-11-20-mode3-passkey-google-signup-design.md`): zkIdP 페이지(3번 탭)의 "패스키로 로그인" 을 아직 연결되지 않은 브라우저에서 누르면
지갑 창이 (패스키가 없으면 "패스키 만들고 계정 만들기" 버튼 한 번 뒤) Google 계정 선택으로 갔다가 돌아와, **Google 이 확인한 이메일을 아이디로** zkIdP 계정을 만들고 등록까지 끝낸 채 로그인된다 — 아이디·비밀번호 가입,
속성 도구, salt·auid 붙여 넣기가 없다(속성은 기본값 1990·KR). 그 뒤 서비스의 "zkIdP 로 로그인" 은 패스키 한 번이다. 이 계정에는 비밀번호가 없다(패스키로만 들어간다). 같은 Google 계정으로는 계정이 하나고,
같은 패스키면 다른 브라우저에서도 그 계정으로 들어간다(패스키를 한 번 더 묻는다). 기존의 "계정 만들기"(아이디·비밀번호)와 속성 도구 순서도 그대로 쓸 수 있다.
이 모드는 실제 Chrome·VM 으로 처음부터 끝까지 리허설해 확인한 것이 아니다(미검증 위험은 `docs/MODE3_DEMO.md` 에 있다).

## zkWrapper 모드(`zkwrapper`)로 할 때 (2026-11-20)

별도 IdP 없이 **zkWrapper** 한 서버(이 PC 의 `https://wallet.zkd.test:5100`)가 지갑 화면과 발급(Google ID 토큰 → 세션 토큰)을 함께 맡는 모드다(스펙 `docs/superpowers/specs/2026-11-20-mode3-zkwrapper-design.md`).
IdP VM(.10)에는 아무것도 띄우지 않는다. 기동은 `WALLET_MODE=zkwrapper ZKWRAPPER_GOOGLE_CLIENT_ID=… AUTO_APPROVE=1 bash scripts/demo_split_start.sh` 이다 — 래퍼 전용 Google 클라이언트 ID 가 없거나
서비스(zkONE·zkTWO)의 ID 와 같으면 아무것도 내리기 전에 멈춘다. Google 콘솔에서 그 클라이언트 ID 의 "승인된 리디렉션 URI" 에 `https://127.0.0.1:5100/google-relay` 를 넣는다.
passkey-web 과 같은 데모 CA·hosts 가 필요하다(`bash scripts/zkd_tls_setup.sh` — 이미 했으면 그대로).

탭은 셋이다: `https://wallet.zkd.test:5100/`(홈 — "zk-Delegation 쓰는 법" 카드 하나: 사용자 세 단계·운영자 세 단계·전체 플로우 링크·"내 세션 관리" 링크), `https://zkone.zkd.test:3100`, `https://zktwo.zkd.test:3101`.
신원·세션·증명·트랜잭션 카드는 **`https://wallet.zkd.test:5100/user`**(내 세션 관리)에 있다(2026-11-24): 처음에는 잠겨 있고 **"패스키로 열기"** 로 연다(그 브라우저의 패스키여야 열린다).
이 탭에서 10분 동안 아무 동작이 없으면 다시 잠기고, "잠그기" 로 바로 잠글 수도 있다. 화면을 가리는 잠금이다 — 저장소 암호화는 그대로다.
"시연: 비밀 바꾸기" 카드는 **`/user?demo=1`** 로 열었을 때만 보인다(2026-11-24 — 시연자의 장면이라 사용자 화면에서 뺐다). 홈 안내 카드의 사용자 1단계 뒤에 승인된 서비스 링크(zkONE·zkTWO)가 있다.
`/user` 의 "보관 상태" 카드에 **"내 계정 폐기"** 가 있다: 확인 창 → Google 계정 선택(같은 계정이어야 한다 — 다른 계정을 고르면 보내지 않는다, 패스키는 묻지 않는다) → 모든 서비스의 로그인이 끝나고
이 계정으로는 다시 로그인할 수 없다(되살리려면 관리자 삭제 뒤 다시 가입 — 같은 패스키면 같은 PPID). 리허설 계정으로는 누르지 않는다.
운영자 화면(`/rp`)·관리자 화면(`/admin`)도 zkWrapper 주소에 있다. 서비스의 로그인 버튼은 **"zkWrapper 로 로그인"** 이다: 누르면 창이 Google 계정 선택으로 갔다가 돌아와 패스키를 한 번 묻고(처음이면 "패스키 만들고 로그인"
버튼 한 번), 로그인이 끝난다. 처음 로그인이 곧 등록이다 — 계정은 Google 계정이고(아이디는 Google 이 확인한 이메일), 속성은 속성 도구 기록이 있으면 그것, 없으면 **비어 있다**(2026-11-24 — 기본값 1990·KR 을 없앴다).
속성이 비어 있으면 조건이 없는 서비스(zkONE)는 그대로 되고, 조건을 거는 서비스(zkTWO — 국가 한국·일본)는 Google 로 가기 전에 "속성 커밋먼트가 없습니다" 로 멈추고 창에 속성 도구 링크가 뜬다(패스키도 묻지 않는다).
그래서 zkTWO 전에 한 번: `/user` 를 열어 "보관 상태" 카드의 "salt 보기" 로 salt 를 복사 → `https://wallet.zkd.test:5100/attr.html` 에서 출생연도·국가를 넣고 salt 칸에 붙여 "커밋먼트 만들기" →
zkTWO 에서 다시 "zkWrapper 로 로그인"(이번 로그인이 새 속성으로 사용자 자격증명을 받는다). 말할 것: 빈 속성은 어떤 조건도 증명하지 않는다 — 속성은 사용자가 스스로 넣은 값만 쓴다.
zkIdP 인증 창·아이디·비밀번호·π_IdP 는 없다. 전체 플로우 한 장(`/common/flow.html`)의 아랫줄은 "Google 계정 → 패스키 → 가명 + Google 토큰 → 세션 토큰 → PPID + π_RP" 로 그려진다.
말할 것: zkWrapper 는 누가(어느 Google 계정) 로그인했는지는 알지만 어느 서비스인지는 모른다(arid_s 는 로그인마다 다르다). 브라우저는 체인을 노드에서 직접 읽어 zkWrapper 를 거치지 않는다.
한계: 같은 Google 계정은 처음 쓴 패스키 하나(의 salt)와만 쓴다 — 다른 패스키면 백업이 없을 때 "이 Google 계정은 다른 패스키에 묶여 있습니다", 백업이 있으면 아래 복구 화면이 뜬다. 사용자 자격증명(C_u)은 첫 교체(보통 첫 로그인 뒤 속성을 넣을 때)만 바로 되고,
그다음 교체(속성을 또 바꾸거나 다른 브라우저에서 처음 로그인)는 앞 교체 뒤 10분이 지나야 된다.
이 모드는 실제 Chrome·VM·실제 Google 로 처음부터 끝까지 리허설해 확인한 것이 아니다(격리 테스트와 대역 Google 로만 확인했다).

**백업과 패스키 분실 복구(2026-11-24, salt 봉투)**: 패스키를 잃어도 같은 계정 주소(같은 PPID)로 돌아오는 장면이다. 준비물은 두 번째 인증기다 — 보안 키, 또는 같은 PC 의 두 번째 Chrome 프로필(새 기기 역할).
1. 백업 만들기(평소 브라우저): `5100/user` 를 패스키로 연다 → **"백업"** 카드의 **"백업 패스키 더하기"** → 확인 창 → Google 계정 선택(같은 계정이어야 한다) → 돌아온 화면에서
   **"① 지금 패스키로 확인"**(지금 패스키 한 번) → **"② 백업 패스키 만들기"**(패스키 창에서 보안 키·다른 기기를 고른다 — 지금 패스키와 같은 인증기는 거절된다) → `/user` 로 돌아와 "백업을 더했습니다", 목록에 "백업 패스키".
   **"복구 코드 만들기"** 도 같은 왕복이다: 돌아온 화면에서 27글자 코드를 **한 번만** 보인다 → 적는다 → "적었습니다" → 다시 입력 → "확인하고 저장"(지금 패스키 한 번). 코드는 Google 로 가기 전에 만들지 않고 어디에도 저장하지 않는다.
   말할 것: zkWrapper 서버에는 salt 를 백업의 열쇠로 잠근 **암호문만** 간다 — salt·코드·패스키 값은 모른다. 백업과 Google 계정이 함께 있으면 계정을 되찾을 수 있으니 백업은 안전한 곳에 둔다. 동기화되는 패스키를 권장한다.
2. 복구(새 기기 — 두 번째 프로필): zkONE 에서 "zkWrapper 로 로그인" → 같은 Google 계정 → "패스키 만들고 로그인" → 발급이 거절되고 **복구 화면**이 뜬다("이 계정에는 백업이 있습니다") →
   **"백업 패스키로 복구"**(보안 키를 대고 한 번) 또는 **"복구 코드로 복구"**(적어 둔 코드를 넣는다 — 한 글자 틀리면 "한 글자가 틀렸습니다", 그 자리에서 고쳐 넣는다) → 로그인 성공. 서비스의 계정 주소가 평소 브라우저와 **같다**.
   새 패스키를 만들면 패스키를 세 번 묻는다(만들기 1 + 확인 1 + 백업 패스키 1, 복구 코드면 두 번). 복구는 Google 확인 뒤 10분 안에 끝내야 하고, 서비스 창은 5분을 기다린다 — 코드는 미리 꺼내 둔다.
   그 뒤 그 기기에서는 새 패스키 한 번으로 로그인한다(이 기기의 사본을 연다).
3. 지우기: `/user` 의 백업 목록에서 **"지우기"** → 확인 창 → Google 계정 선택 → 돌아온 화면에서 **"지금 패스키로 확인하고 지우기"**(지금 패스키 한 번) → `/user` 로 돌아와 "백업을 지웠습니다".
   말할 것: 지운 백업으로는 더 복구할 수 없지만, **이미 복구한 기기는 끊기지 않는다**(그 기기에 사본이 있다). 더하기·지우기 모두 패스키를 묻는 까닭 — Google 계정만 빼앗은 사람은 백업을 지우거나
   한도(5개)를 쓸모없는 백업으로 채우지 못한다(요청에 이 계정의 auid 를 싣고 서버가 맞춰 본다, 2026-11-24 최종 검토 I-1).
이 기기의 사본이 망가지면(저장소 손상 등) 로그인이 "백업을 열지 못했습니다" 로 멈춘다 — `/user` "보관 상태" 의 "모두 지우기" → "패스키 연결 끊기" 뒤 서비스에서 다시 로그인하면 복구 화면이 뜬다.
한계: 서버가 봉투를 숨기거나(백업이 없다고 하거나) 지우면 브라우저는 막지 못한다 — 백업은 서버가 정직하게 내줄 때만 쓸 수 있다. 백업을 연 뒤의 auid 대조도 정직한 서버를 전제로 한 검사다(서버가 옛 봉투와 옛 대조값을 함께 주면 못 가린다).
복구한 기기의 첫 발급은 사용자 자격증명(C_u) 교체라서, 그 계정의 앞 교체(속성 변경·다른 복구) 뒤 10분 안에는 "사용자 자격증명을 방금 바꿨습니다" 로 막힌다 — 리허설에서는 속성을 바꾼 직후에 복구하지 않는다.
복구한 기기에는 속성 도구 기록이 없어 다음 발급의 사용자 자격증명이 **빈 속성**의 C_u 가 된다 — 조건을 거는 서비스(zkTWO)를 쓰려면 그 기기에서 속성 도구로 속성을 다시 넣는다.
백업 패스키를 만든 뒤 저장까지 끝나지 않으면(한도 5개·취소) 인증기에 쓰이지 않는 패스키가 남을 수 있다 — 지워도 된다. `/user` 의 백업 목록은 그 브라우저가 받은 응답으로만 바뀐다 — 다른 기기에서 더한 백업은 이 브라우저에서 다음에 더하거나 지울 때 나타난다.
이 장면도 실제 Google·실제 보안 키로는 아직 리허설하지 않았다(대역 Google·가짜 인증기로 격리 테스트만 했다).

**옛 증명으로 보내기(시연, 2026-11-23)**: 서비스의 "온체인 출금" 묶음에 **"① 증명 만들어 두기(시연)"** 와 **"② 옛 증명으로 보내기(시연)"** 버튼이 있다(zkWrapper 로그인 중일 때만 보인다).
root 가 바뀐 경우만 보인다. 순서: (zkTWO 에도 같은 Google 계정으로 로그인해 둔다) → zkONE 에서 ① 을 누른다(지금의 root·nonce 로 증명만 만들고 보내지 않는다, 패스키 한 번) →
zk 클라이언트의 내 세션 관리(`5100/user`, 패스키로 연다)의 zkTWO 세션 카드에서 **"이 세션 끝내기"** → Google 계정 선택(패스키는 묻지 않는다) → `/user` 로 돌아와 "zkTWO 세션을 끝냈습니다" →
관리자 화면(`/admin`)의 "폐기 목록" 에서 "게시"(또는 하트비트 게시를 기다린다) → zkONE 으로 돌아와 ② 를 누른다.
세션 끝내기는 사용자 본인이 한다 — 1회용 요청 키에 묶인 Google 토큰과 그 키의 서명으로 zkWrapper 가 본인 확인을 한다(π_IdP 없음, 세션 전체 폐기만).
다른 Google 계정으로 돌아오면 거절된다. 관리자 화면의 **계정** 카드(zkWrapper 에서만 보인다)의 "세션" → "폐기" 로 운영자가 끊을 수도 있다. ② 는 ① 의 증명값(a·b·c)을 그대로 두고 공개 입력의 root 만 지금 값으로 바꿔 보낸다 —
nonce 는 ① 때 그대로라 nonce 검사는 통과하고, 거래는 블록에 실려(Blockscout 에 실패로 보인다) 계정 컨트랙트의 증명 검증에서 `InvalidProof` 로 되돌려진다.
화면에 거래 해시와 "RCL root (생성 당시 값 / 현재 값)" 두 줄이 서로 다른 값으로 뜬다. 말할 것: 증명은 그것을 만들 때의 root 에 묶여 있어, 폐기 목록이 바뀐 뒤에는 다시 쓸 수 없다.
root 가 아직 그대로면 ② 는 보내지 않고 "root 가 아직 바뀌지 않았습니다" 로 거절한다(보내면 진짜 출금이 된다). ① 을 하지 않았거나 그 뒤 출금으로 nonce 가 바뀌었으면 "지금 nonce 로 만들어 둔 증명이 없습니다" 로 거절한다 —
nonce 때문에 실패하는 장면(한 번 쓴 증명의 재사용)은 다음 버전에서 따로 보인다. 관리자 화면의 계정 카드는 zkWrapper 모드에서만 보인다(다른 모드는 11-11 결정대로 숨김). 이 시연은 릴레이가 되돌려질 거래도 보내야 해서 서비스가 `MODE3_RELAY_DEMO_REVERT=1` 일 때만 열리고,
분리 데모 스크립트는 기본으로 켠다(`RELAY_DEMO_REVERT=0` 이면 끔). "출금 출처" 선택칸은 없앴다 — zkWrapper 로그인이면 내 계정(PPID), Google 일반 로그인이면 거래소 보관에서 나간다.
세션 수명 기본은 5블록이다(자연 만료 시연용) — 다른 서비스의 배포·출금으로 블록이 쌓이면 먼저 로그인한 서비스가 만료로 풀린다. 두 서비스를 오가며 보일 때는 `TTL_BLOCKS=300` 으로 띄운다.

## 다시 로그인

- **zkIdP 가 새 판을 게시할 때마다** zkONE·zkTWO 의 열려 있던 로그인이 모두 닫힌다. 폐기(누구의 폐기든)뿐 아니라 **등록부가 바뀔 때도** 그렇다 — 누군가의 첫 로그인(첫 발급)·속성 변경·계정 폐기. 12 의 새 계정 첫 로그인도 다른 서비스의 로그인을 닫는다. 화면은 그대로 두고 내 자산 위에 "이 로그인은 닫혔습니다" 안내가 뜬다. 탭으로 돌아오거나 요청이 거절되는 즉시, 늦어도 10초 안에 뜬다.
- 다시 로그인하는 길: 안내의 "로그아웃하고 다시 로그인" → "로그인" → "zkIdP 로 로그인" → 아이디·비밀번호·auid → "로그인".
- auid 는 70자리가 넘는 숫자다. 2 에서 복사한 값을 메모장에 붙여 두고 거기서 가져온다. 잃었으면 3번 탭 "내 정보" 의 auid 옆 복사 버튼.
- 안내가 뜨기 전에 출금·구매를 누르면 `세션을 다시 검증해야 합니다` 실패가 보인다. 오류가 아니라 같은 일의 다른 표시다 — 곧 안내가 함께 뜬다.
- 다음 단계에서 쓰지 않을 서비스는 다시 로그인하지 않아도 된다(예: 9·10 에서 zkTWO).

## 막혔을 때

| 보이는 것 | 할 일 |
|---|---|
| 팝업이 `스냅이 옛 버전입니다` 로 멈춘다 | 시연 중에는 고치지 않는다. 끝난 뒤 체크리스트 S15 |
| zk 스냅 화면에 탭 대신 "스냅 설정 — salt 와 백업" | salt 가 없다 — "백업에서 불러오기" → 백업 파일·비밀번호(체크리스트 S16) |
| 서비스 로그인이 `이 스냅은 이 IdP 에 이미 다른 계정으로 등록돼 있습니다` | 앞 리허설의 등록이 남았다 — 그 계정으로 로그인하거나, 리셋 뒤라면 "스냅 초기화" |
| 로그인이 `속성 커밋먼트 기록의 uid 가 다릅니다` | zkIdP 계정을 바꿨다 — 그 계정으로 로그인한 채 2번 탭에서 "커밋먼트 만들기" 를 다시 누른 뒤 로그인 |
| Race (2) 에서 2블록 쪽이 막힌다 | 앞에서 끝낸 세션(8)을 "게시" 하지 않고 넘어왔다 — 남아 있던 자동 게시가 이번 폐기까지 올린 것이다. 4번 탭에서 "게시" 한 뒤 다시 로그인해 한 번 더 |
| Race (2) 에서 5블록 쪽도 통과한다 | 팝업 진행 줄이 끝까지 "RCL root 그대로" 였는지 본다 — 게시·중계가 늦었다. 다시 로그인해 한 번 더 |
| Race (2) 창에서 "5블록 뒤 보내기"(또는 둘 다)가 꺼져 있다 | 세션 수명이 모자란다(창 아래에 "이 세션은 N블록 뒤 만료됩니다") — 다시 로그인하면 수명이 새로 잡힌다. 자주 그러면 `TTL_BLOCKS=30` 으로 띄운다(기본 5 는 Race (2) 에 모자란다) |
| Race (2) 결과가 `계정 안 송금이 실패했습니다` | 세션 검사는 통과했는데 내 계정 ETH 가 금액보다 적다 — "ETH 구매" 뒤 다시 로그인해 한 번 더 |
| 출금 팝업이 5분 넘게 멈춰 있다 | 서비스가 창을 닫고 `timeout` 으로 끝낸다 — 다시 누른다 |
| 로그인이 `expired` 로 끊긴다 | `TTL_BLOCKS` 가 작다 — 다시 로그인. 다음에는 `TTL_BLOCKS=30` 으로 띄운다 |
| 입금·구매가 계속 `같은 요청을 다시 보냈습니다`(request_replayed), 또는 로그인이 모두 `bad_id_token` | VM 시계가 어긋났다(일시 중지 뒤 재개 등) — 시작 스크립트의 "시계가 … 어긋난다" 경고를 본다. VM 에서 이 PC 의 시각으로 맞춘 뒤 다시 |
| 서비스 요청이 모두 `폐기 목록이 너무 오래 게시되지 않았습니다`(root_too_old) | 응용 체인 거래가 거울 갱신 없이 쌓였다(폐기 체인은 게시 때만 블록이 생겨 하트비트가 돌지 않는다). zkIdP 관리자 화면 4번 탭의 "거울 다시 맞추기" — "게시" 는 올릴 변경이 없으면 아무것도 하지 않는다 |

### 실제 Google · 일반 OIDC 를 보이기 전에 볼 것(2026-11-19 리뷰)

- **서비스 VM 의 인터넷**: Google 토큰 검증은 서비스 서버(VM .11·.12)가 `https://www.googleapis.com/oauth2/v3/certs` 를 직접 받는다. 각 VM 에서 `curl -sI https://www.googleapis.com/oauth2/v3/certs` 가 200 인지 본다(안 되면 `oidc_unavailable`).
- **VM 시계**: 토큰의 시각 허용 오차는 60초다. VM 시계가 그보다 어긋나면 로그인이 실패한다.
- **Google 콘솔**: "승인된 리디렉션 URI" 에 `https://127.0.0.1:5100/google-relay` 를 글자 그대로(서비스의 클라이언트와 zkIdP 의 클라이언트 — 여덟째의 패스키 가입 — 모두. 같은 클라이언트 ID 를 함께 쓰면 한 번만 넣는다). 동의 화면이 "테스트" 상태면 시연 계정을 테스트 사용자로 넣는다.
  서비스마다 다른 클라이언트 ID(`RP1_GOOGLE_CLIENT_ID`·`RP2_GOOGLE_CLIENT_ID`)를 주지 않으면 두 서비스의 aud 가 같게 찍힌다(시작 스크립트가 경고한다).
- **같은 탭으로 돌아오기**: Google 을 다녀오는 동안 탭을 바꾸지 않는다. 10분 안에 돌아와야 한다.
- **일반 OIDC(예비)로 보일 때**: zkIdP 관리자 표의 "일반 OIDC 에서 본 서비스" 는 마지막 서비스 하나만 보인다 — zkONE 로그인 뒤 표를 한 번 보이고, zkTWO 로그인 뒤 다시 보인다(rid 가 바뀐 것이 "zkIdP 는 어느 서비스인지 안다" 다).
  서비스가 승인되기 전에는 "일반 OIDC · 비교용" 버튼이 보이지 않는다.
